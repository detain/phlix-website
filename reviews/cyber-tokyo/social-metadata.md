## ⚠️ Concerns (non-blocking)

- **`og:image` points to `og.png` but only `og.svg` exists in `img/`**: The spec §8 requires `og.png` (1200×630 raster). If the build pipeline rasterizes `og.svg` → `og.png`, the metadata is correct. If not, social preview images will fail to load on Twitter/LinkedIn/Facebook. — Verify the build converts `og.svg` → `og.png`. See brand-fidelity review.
- **All pages share identical `og:title`, `og:description`, `og:image`**: While technically correct (all pages pass the OG required fields), this means every page shares the same social preview. Pages like about, hub, plugins don't override with page-specific social copy. For SEO and sharing, page-specific OG tags would be more optimal. — Non-blocking for a static marketing site; acceptable.

## ❌ Failures (must fix this round)

- **`sitemap.xml` priority for about.html is 0.6 but it should have proper priority for a content-heavy page**: The about page has FAQ content and project information — it should not be the lowest priority (0.6). However, this is a sitemap concern, not strictly social metadata. — Not a social metadata failure; handled in SEO review.
- **`img/og.png` missing from `img/` directory**: Only `og.svg` exists. All 8 HTML pages reference `og.png`. If `og.png` is not generated by the build, social previews will return 404 errors and fall back to no image. — Ensure build generates `og.png` at 1200×630 resolution from the `og.svg` source. This is a **critical blocker** for social sharing.
