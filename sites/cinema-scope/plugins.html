Plugins

Extend Phlix with a versioned plugin contract. Drop in, the loader picks it up.

Plugin Model

Phlix plugins implement the LifecycleInterface and ship a manifest file. The plugin loader discovers, validates, and manages the plugin lifecycle automatically.

LifecycleInterface

Every plugin must implement these methods:

  • onInstall() — called when the plugin is first enabled
  • onEnable() — called each time Phlix starts with the plugin enabled
  • onDisable() — called when the plugin is disabled
  • onUninstall() — called when the plugin is removed

Manifest

Each plugin needs a manifest.json at its root:

manifest.json 
{
  "name": "my-metadata-provider",
  "version": "1.0.0",
  "description": "Fetches metadata from MyAPI",
  "author": "Your Name",
  "license": "MIT",
  "lifecycle": "metadata-provider",
  "config": {
    "api_key": {
      "type": "string",
      "required": true
    }
  }
}

Drop-in Installation

Place your plugin in the plugins/ directory and Phlix will detect it on the next startup. Enable via the admin interface or API.

Ecosystem Plugins

Community and reference plugins for common use cases. See phlix-plugin-example as a starting point.

Write Your Own

The phlix-plugin-example repository contains the smallest working plugin — a reference metadata provider you can fork and customize.

It includes:

  • Complete LifecycleInterface implementation
  • Working manifest with config schema
  • Example of fetching external metadata
  • Tests you can run locally
