Plugins

Extend Phlix with a versioned plugin contract — not an afterthought.

Plugin Model

Phlix implements a first-class plugin system with a versioned manifest contract. Plugins are not second-class citizens bolted on after the fact — they're a first-class extension point with proper lifecycle management.

LifecycleInterface + manifest

  • Implement LifecycleInterface in your plugin class
  • Ship a manifest.json describing name, version, author, and dependencies
  • Drop the plugin into plugins/
  • The plugin loader picks it up automatically on next server restart
  • No code modification to the core required

Ecosystem Plugins

The Phlix ecosystem already includes plugins for metadata providers, custom transcoders, authentication backends, and more. Browse the GitHub org for community-contributed plugins.

Write Your Own

Start with phlix-plugin-example — the reference metadata-provider plugin that demonstrates every part of the plugin contract. It shows how to declare a manifest, implement lifecycle hooks, define service providers, and expose metadata to the system.

Clone the example plugin

git clone https://github.com/detain/phlix-plugin-example.git
cd phlix-plugin-example
# read README.md to get started
