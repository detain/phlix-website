Plugins

Extend Phlix with a versioned plugin contract. Drop in a plugin, the loader picks it up.

Plugin Model

Each plugin implements LifecycleInterface and ships a manifest.json that declares the plugin's version, the Phlix version it targets, and the services it provides. The loader validates the manifest before activating the plugin, so a broken plugin can't crash your server.

  • LifecycleInterface — onInstall(), onEnable(), onDisable(), onUninstall()
  • Manifest schema — versioned, so plugins written for Phlix 1.x keep working when you upgrade to 2.x
  • Drop-in loading — place your plugin in plugins/, the loader discovers and activates it automatically
  • Service providers — plugins can expose metadata providers, transcoding profiles, or custom route handlers

Getting started

Start from phlix-plugin-example. It shows the minimal structure: a manifest, a plugin class, and one metadata provider. Fork it, rename it, and you have a working plugin in under five minutes.

The docs cover the plugin contract, the service provider interface, and how to publish your plugin to the ecosystem.
