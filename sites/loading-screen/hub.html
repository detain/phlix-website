Phlix Hub

Access your home server from anywhere — without opening ports, buying a static IP, or trusting a third-party tunnel service.

What the Hub does

The Hub is two things: a cloud directory and a reverse-tunnel relay.

When your Phlix server starts, it establishes an outbound tunnel to the Hub. The Hub assigns it a unique identifier and registers it in your account's server list. When you open a client and sign in, it fetches your server list from the Hub and connects — directly when you're on the same network, through the relay when you're away.

The reverse-tunnel relay handles NAT traversal. Your server initiates the connection, so you never need to port-forward or configure firewall rules. The relay proxies traffic bidirectionally — your media flows through it only when necessary, and the connection is encrypted the whole way.

Self-host or use the public hub

The public Hub at github.com/detain/phlix-hub is free to use. If you want full control — or if you want to run multiple accounts for family or a small team — you can self-host the Hub on any PHP 8.3+ server.

Self-hosting the Hub means your server-to-hub traffic terminates on infrastructure you control. The relay still proxies media when you're off-network, but the directory and authentication live on your own server.

Hub mode in clients

Hub mode is built into every Phlix client. When you sign in, the client checks for registered servers. If it finds your home server registered through the Hub, it offers both local and remote access — the client automatically picks the best path.

Roku, Samsung Tizen, Windows, and Mobile all support Hub mode. DLNA discovery works only on the local network, but every native client can reach your server anywhere in the world.
