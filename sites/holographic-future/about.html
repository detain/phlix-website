Chapter I

Philosophy

Phlix is built on a single conviction: your media library is yours. Not a platform's. Not a streaming service's. Yours — stored on hardware you own, in a room you control, accessible on your terms. Every design decision in Phlix starts from that premise: the library doesn't leave your hardware unless you say so. The server doesn't expose itself to the internet unless you configure it. Your viewing habits don't become a product.

This extends to the software itself. Phlix is open source. You can read it, fork it, extend it, and self-host it. The Hub relay is open source too — you can run your own, or use the public one. There is no free tier with a usage cap. There is no premium tier with features behind a paywall.

Chapter II

License

Phlix Server and the Hub are MPL-2.0 — open source, and you can build on them commercially. If you modify a Phlix file, that file stays open; anything you add alongside it is yours. The shared libraries, plugins, and clients are MIT so you can build on them freely.

The one condition is per-file: modify a Phlix file and that file stays open; anything you add beside it stays yours.

Chapter III

Contributing

Phlix is maintained by the detain GitHub org. Issues, pull requests, and plugin submissions are welcome. The plugin system is designed to make contribution independent of core development — a well-structured plugin with a manifest and tests can be maintained separately from the server.

If you find a bug, open an issue. If you want to contribute code, open a pull request against detain/phlix-server or one of the client repositories.

Lux's Calibration Guide

Frequently asked questions

Is Phlix like Plex / Jellyfin / Emby?
Yes — same job, different stack. Phlix is built in PHP 8.3+ on Workerman, ships with a versioned plugin contract, and includes a hub for accessing remote servers behind NAT without a third-party tunnel.
Do I need to expose my server to the internet?
No. Run Phlix on your LAN and use the Phlix Hub's reverse-tunnel relay to reach it from your phone or Roku at a friend's house. You can self-host the hub, or use the public one.
Can the hub run on my own server instead of the cloud?
Yes — the Hub is self-hostable. See the hub admin documentation for install instructions.
Do all my devices need to be on the same Wi-Fi?
No — Hub mode reaches your server across NAT boundaries. As long as the client is signed into the same Hub account as your server, they connect regardless of network location.
What formats are supported?
Anything FFmpeg can read. Direct play when the client supports it; transcoded HLS otherwise. Per-device quality profiles pick the right bitrate automatically.
Does it transcode in real-time if my network is slow?
Yes — the adaptive HLS streaming detects available bandwidth and switches to a lower bitrate variant in real time. The quality selector profiles (mobile-low, mobile-high, web, tv-4k) handle the breakpoints.
Is there a mobile app?
Yes — React Native, available on iOS and Android. Currently in beta.
Can I write plugins?
Yes. Implement LifecycleInterface, ship a manifest, drop it in the plugins directory. See phlix-plugin-example for the smallest working starter.
What's the license?
Phlix Server and the Hub are MPL-2.0 — open source, and you can build on them commercially. If you modify a Phlix file, that file stays open; anything you add alongside it is yours. The shared libraries, plugins, and clients are MIT so you can build on them freely.
