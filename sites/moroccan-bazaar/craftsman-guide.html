Writing a plugin

Every plugin starts with a manifest.json and a class that implements LifecycleInterface. The four lifecycle hooks — onInstall, onEnable, onDisable, and onUninstall — let your plugin react to its own lifecycle and to events in the server.

The contract version in your manifest must match a version Phlix understands. The loader logs a warning and skips mismatched plugins — it will not crash the server.

Building a brand kit

A Phlix brand kit is a JavaScript module in brand-kits/. It defines the full visual identity — colors, typography, spacing, motion, mascot behaviour, and experience overrides — in one self-contained file. The site generator reads the kit and produces a fully themed static site.

Key fields: design_tokens (CSS custom properties), fonts (self-hosted WOFF2), colors, mascot, and the experience override fields like homepage_narrative and navigation_model.

Contributing to Phlix

Start with the issue tracker. Look for tickets labelled good first issue or help wanted. If you want to add a feature, open an issue first to discuss the design — a PR that solves the wrong problem is expensive for both sides.

The detain GitHub org maintains the core server, hub, and official clients. Plugin ecosystem lives in community repos. All contributions are welcomed.
