Plugins

A plugin system with a real contract

LifecycleInterface + manifest schema. Drop a plugin in, the loader picks it up. The contract is versioned — a plugin you write today still works when Phlix ships new releases.

How it works

Each plugin lives in its own directory under plugins/ and announces itself with a manifest.json. The loader reads every manifest on startup, validates the contract version, and registers the plugin's hooks. If a plugin's contract version doesn't match, Phlix logs a warning and skips it — it won't crash the server.

plugins/phlix-plugin-example/manifest.json
{ "name": "phlix-plugin-example", "version": "1.0.0", "contract": "1.0", "description": "Reference metadata-provider plugin", "entry": "src/Plugin.php" }

Your plugin's main class implements LifecycleInterface, which gives Phlix four hooks: onInstall, onEnable, onDisable, and onUninstall. Add a film and the scanner calls your provider; add a channel and the guide manager queries your EPG.

Ecosystem plugins

The Phlix ecosystem already has plugins for metadata providers, additional EPG sources, and channel lineups. Check the phlix-plugin-example repository for the smallest working starter — clone it, rename it, and you have a working plugin in minutes.

Write your own

The reference implementation at phlix-plugin-example shows the full lifecycle, manifest schema, and scanner integration. The contract is documented in the developer docs.
