About Phlix

Self-hosted media, built in the open, designed to stay in your control.

Philosophy

Your media library is personal. It's your photos from the last decade, the shows you've watched with your family, the music that's been the backdrop to your life. It shouldn't live on someone else's server, behind someone else's paywall, subject to someone else's terms of service.

Phlix exists because you should be able to run your own media infrastructure. Not because self-hosting is free (it isn't — you pay for the hardware and electricity), but because control matters. When you run Phlix, you own the server, the database, the metadata, and the connections. If you want to shut it down, it shuts down. If you want to move it somewhere else, you move it. No one else can decide for you.

The architecture reflects this: a simple PHP server, standard protocols where they make sense (DLNA, HLS), and a plugin system that's actually a plugin system — not a walled garden.

License

Phlix uses a split licensing model that keeps the core open while allowing commercial use:

  • Phlix Server and Phlix Hub are MPL-2.0. If you modify a file in either project, that file stays open. Anything you add alongside it is yours.
  • Phlix Shared, plugins, and clients are MIT. Build on them freely, include them in proprietary products, whatever — the MIT license puts almost no restrictions on what you can do.

This isn't a license designed to make Phlix look open while being practically restrictive. It's the same license Mozilla uses for Firefox, and it means exactly what it says: if you improve the server, the server improvements are yours to share but not required to share. The freedom is real.

Contributing

The project lives at the detain GitHub org. The server, hub, clients, plugins, and documentation are all open to issues and pull requests.

If you're looking to contribute:

  • phlix-server issues — bugs and feature requests for the core server
  • phlix-plugin-example — the reference plugin; a good place to learn the system
  • phlix-docs — documentation improvements are always welcome

For significant changes, open an issue first to discuss what you're planning. Small fixes and typo corrections can go straight to a PR.

Frequently asked questions

Is Phlix like Plex / Jellyfin / Emby?

Yes — same job, different stack. Phlix is built in PHP 8.3+ on Workerman, ships with a versioned plugin contract, and includes a hub for accessing remote servers behind NAT without a third-party tunnel.

Do I need to expose my server to the internet?

No. Run Phlix on your LAN and use the Phlix Hub's reverse-tunnel relay to reach it from your phone or Roku at a friend's house. You can self-host the hub, or use the public one.

What formats are supported?

Anything FFmpeg can read. Direct play when the client supports it; transcoded HLS otherwise. Per-device quality profiles pick the right bitrate automatically.

Is there a mobile app?

Yes — React Native, available on iOS and Android. Currently in beta.

Can I write plugins?

Yes. Implement LifecycleInterface, ship a manifest, drop it in the plugins directory. See phlix-plugin-example for the smallest working starter.

What's the license?

Phlix Server and the Hub are MPL-2.0 — open source, and you can build on them commercially. If you modify a Phlix file, that file stays open; anything you add alongside it is yours. The shared libraries, plugins, and clients are MIT so you can build on them freely.
