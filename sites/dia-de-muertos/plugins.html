Plugins

A versioned contract. A manifest schema. Drop a plugin into the directory and the loader picks it up — no ceremony required.

The Plugin Model

Every plugin implements LifecycleInterface and ships a manifest file. The loader reads the manifest, validates the version, and calls the appropriate lifecycle method. If the manifest is absent or the version incompatible, the plugin is skipped silently — it cannot break the server.

LifecycleInterface

Hook points

  • onInstall() — first time the plugin is found
  • onEnable() — server startup
  • onDisable() — server shutdown or admin disable
  • onUninstall() — admin removal

Manifest schema

Required fields

  • name — unique plugin identifier
  • version — semver, compared against loader's min version
  • description — shown in the admin UI
  • author, license

Plugins live in plugins/ alongside the server. See phlix-plugin-example for the smallest working starter.
