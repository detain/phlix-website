Plugin Model

How plugins work

Phlix uses a versioned manifest contract (LifecycleInterface + manifest schema) to load and manage plugins. When you drop a plugin into the plugins/ directory, the loader picks it up automatically — no configuration required.

Minimal plugin structure 
plugins/
  my-plugin/
    manifest.json     # Plugin metadata and version
    src/
      Plugin.php      # Implements LifecycleInterface

The manifest declares the plugin's name, version, dependencies, and which lifecycle hooks it responds to. The loader calls your plugin at startup, when media is scanned, and when streaming decisions are made.

Write Your Own

Build something new

You can write plugins for:

  • Metadata providers — Fetch posters, summaries, cast from any source
  • Transcoding profiles — Custom quality selectors or codec preferences
  • Auth providers — SSO, LDAP, or custom credential backends
  • Indexers — Parse unusual file naming conventions or folder structures

Check the docs for the full LifecycleInterface reference and manifest schema.
