About Phlix

A media server you control. Completely.

Philosophy

Phlix is built on a single premise: your media server should serve you, not a company. That means running on hardware you own, under software you can audit, with no subscription, no telemetry, and no third party between you and your library.

PHP is the right tool for this. It runs everywhere, the runtime is fast (Workerman 5.x, async/coroutine), and the ecosystem for media handling — FFmpeg, metadata scrapers, DLNA stacks — is mature and well-understood.

Phlix is not trying to out-feature Plex or Jellyfin on day one. It is trying to be the version of a media server you can run forever without asking permission.

Contributing

Phlix is developed in the open by @detain. Issues, pull requests, and plugin submissions are welcome. The server, clients, hub, and documentation are all in the detain GitHub org.

Before opening a large PR, open an issue to discuss the change. Bug reports with reproduction steps are always welcome.

Frequently Asked

Is Phlix like Plex / Jellyfin / Emby?
Yes — same job, different stack. Phlix is built in PHP 8.3+ on Workerman, ships with a versioned plugin contract, and includes a hub for accessing remote servers behind NAT without a third-party tunnel.
Do I need to expose my server to the internet?
No. Run Phlix on your LAN and use the Phlix Hub reverse-tunnel relay to reach it from your phone or Roku at a friend's house. You can self-host the hub, or use the public one.
What formats are supported?
Anything FFmpeg can read. Direct play when the client supports it; transcoded HLS otherwise. Per-device quality profiles pick the right bitrate automatically.
Is there a mobile app?
Yes — React Native, available on iOS and Android. Currently in beta.
Can I write plugins?
Yes. Implement LifecycleInterface, ship a manifest, drop it in the plugins directory. See phlix-plugin-example for the smallest working starter.
What is the license?
BSD-3-Clause across the board.
