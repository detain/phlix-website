Plugins

A versioned contract, a drop-in loader, a manifest that speaks for itself. The plugin system Phlix deserves.

The plugin model

Every plugin implements LifecycleInterface and ships a manifest.json. Drop the plugin folder into plugins/ and the loader finds it. No registry. No ceremony.

plugins/
  my-metadata-provider/
    manifest.json        # name, version, lifecycle hooks
    src/
      MyPlugin.php      # implements LifecycleInterface

The manifest declares which lifecycle events the plugin responds to: onboot, onscan, onmetadata, onshutdown. The loader invokes them in turn.

Ecosystem plugins

The community grows the circle. Once a plugin is stable, consider adding it to the Phlix ecosystem listing.

Write your own

The reference implementation is the smallest possible working plugin. Study it, then weave your own.

https://github.com/detain/phlix-plugin-example

The example covers the full lifecycle: manifest authoring, service registration, metadata enrichment, and graceful shutdown. It is the illuminated initial letter — everything else begins here.
