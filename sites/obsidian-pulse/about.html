About Phlix

Signal. Refined.

Philosophy

Built not decorated.

Phlix is a self-hosted PHP media server. It was built in PHP 8.3+ on Workerman because that stack runs everywhere and the architecture is simple: one process handles the DLNA stack, one handles the web lobby, one handles transcoding, and they share a database.

The plugin system uses a versioned LifecycleInterface contract — drop a plugin in, the loader picks it up. The Hub uses a reverse-tunnel relay so your server on a home network is reachable without touching your router. SyncPlay uses weighted-mean NTP offset over 5 samples so everyone stays on the same frame.

The guiding principle is restraint. Every feature has to justify its existence. A media server's job is to get out of the way between your library and your screen.

FAQ

Technical reference.

Is Phlix like Plex / Jellyfin / Emby?

Yes — same job, different stack. Phlix is built in PHP 8.3+ on Workerman, ships with a versioned plugin contract, and includes a hub for accessing remote servers behind NAT without a third-party tunnel.

Do I need to expose my server to the internet?

No. Run Phlix on your LAN and use the Phlix Hub's reverse-tunnel relay to reach it from your phone or Roku at a friend's house. You can self-host the hub, or use the public one.

What formats are supported?

Anything FFmpeg can read. Direct play when the client supports it; transcoded HLS otherwise. Per-device quality profiles pick the right bitrate automatically.

Is there a mobile app?

Yes — React Native, available on iOS and Android. Currently in beta.

Can I write plugins?

Yes. Implement LifecycleInterface, ship a manifest, drop it in the plugins directory. See phlix-plugin-example for the smallest working starter.

What's the license?

Phlix Server and the Hub are MPL-2.0 — open source, and you can build on them commercially. If you modify a Phlix file, that file stays open; anything you add alongside it is yours. The shared libraries, plugins, and clients are MIT so you can build on them freely.

Who uses Phlix

Three surfaces.

The Home Lab Architect

A power user with a dedicated server cabinet in the basement: running Phlix on bare metal, configuring per-device transcoding profiles, monitoring SyncPlay latency across five devices in real time.

The Privacy Perfectionist

A household that values data sovereignty: Phlix server on their own hardware, Hub self-hosted in their own colocation, every connection encrypted, no cloud dependency.

The Multi-Room Enthusiast

Four rooms, five devices, SyncPlay enabled: movie starts in the living room, user walks to the kitchen mid-scene and continues seamlessly on the TV there, all devices locked to the same frame.
