Plugins

Extend Phlix with a clean, versioned plugin contract. Drop it in, the loader picks it up.

The plugin model

Every plugin implements LifecycleInterface and ships a manifest.json. The loader scans the plugins/ directory on startup and registers each plugin's hooks and services automatically.

LifecycleInterface

The core interface requires two methods:

  • onEnable() — called when the plugin is activated
  • onDisable() — called when the plugin is deactivated

manifest.json

Each plugin must provide a manifest declaring its name, version, and dependencies:

{
  "name": "my-metadata-provider",
  "version": "1.0.0",
  "description": "Fetches metadata from MyService",
  "require": {
    "phlix/core": ">=2.0"
  }
}

See phlix-plugin-example for the smallest working starter.

Write your own

The plugin system is designed around the principle that adding a feature should feel like stepping off the dock — smooth and unhurried. You bring the logic; Phlix handles the wiring.

Start from the reference plugin and build out from there. The docs cover the full hook system, service registration, and event types.
