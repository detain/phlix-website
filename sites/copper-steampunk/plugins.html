Plugins

The apparatus is designed for extension. A versioned contract, a clear manifest, and a loader that does the rest — drop a plugin in, and the mechanism engages.

Plugin Model

Phlix plugins implement the LifecycleInterface and ship a manifest.json. The server discovers plugins by scanning the plugins/ directory on startup.

  1. Create a manifest.json declaring your plugin's name, version, dependencies, and the fully-qualified class name of your LifecycleInterface implementation.

  2. Implement onEnable(), onDisable(), and optionally onInstall() and onUninstall() hooks.

  3. Drop the plugin directory into your Phlix server's plugins/ directory.

  4. The loader validates the manifest, calls onEnable(), and registers your plugin's routes and services automatically. 

{
  "name": "my-metadata-provider",
  "version": "1.0.0",
  "entry": "MyMetadataProvider\\Plugin",
  "requires": {
    "phlix-server": ">=4.0.0"
  }
}

Reference Plugin

phlix-plugin-example is the smallest working starter. It demonstrates a metadata provider plugin: it parses an additional file format, contributes its own database table, and exposes a single API endpoint. Study it, then build from that foundation.
