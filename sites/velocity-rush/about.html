// 01 / PHILOSOPHY

Zero wait. Full stop.

Phlix exists because most media servers treat speed as a feature request. We treat it as a design constraint. Every component is measured in milliseconds — library scan time, sync drift, transcoding latency, and playback start time.

The web interface is a thin client. The server does the work. SyncPlay uses NTP-style time synchronization so everyone in a watch party stays locked to the same frame, not approximately the same timestamp. The library scanner uses file mtime hashing, not full-file hashing — adding content is O(1) relative to the folder size.

Phlix is open source under MPL-2.0. Modify a Phlix file and it stays open. Fork it, extend it, break it, fix it. The goal is a media server that earns the term "instant."

// 03 / CONTRIBUTING

Contributing

Issues, pull requests, and plugin submissions are welcome. The core server is PHP 8.3+ with a focus on clean architecture — PSR-12 coding style, strict types, and documented public APIs.

For major changes, open an issue first to discuss the direction. For bug reports, include your PHP version, OS, and steps to reproduce. For feature requests, describe the problem you're solving, not just the solution.

All contributors must follow the project's code of conduct. Be constructive, specific, and kind.

// 04 / FAQ

Telemetry Log

Phlix is self-hostable like Plex/Emby but written in PHP with a focus on raw performance. SyncPlay is native and NTP-based (not WebSocket approximation). The server is a single PHP application — no Java, no Node.js, no Docker required for basic use. The tradeoff is a narrower client ecosystem: Roku, Samsung Tizen, Windows, Android, and web — not every platform.
