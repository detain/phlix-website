Plugin architecture

Extensions

A real contract. A versioned manifest. Drop a plugin in and the loader picks it up — no registry, no ceremony, no lock-in.

The contract

Every plugin implements LifecycleInterface and ships a manifest file. The loader reads the manifest, validates the version constraint, and registers the plugin's hooks. That is the entire API surface — precise, documented, stable.

Plugin manifest (manifest.json) { "name": "my-metadata-provider", "version": "1.0.0", "phlix_version": ">=4.0.0", "entry": "MyMetadataProvider.php", "hooks": ["metadata.scan", "library.item.created"] }

Drop the plugin directory into plugins/. Phlix discovers it on the next scan. No install step. No database migration for plugins.
