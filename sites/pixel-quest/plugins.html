Plugins

Phlix has a real plugin contract — not a hack, not an afterthought. Versioned interface, manifest schema, drop-in discovery.

How the plugin system works

1. Implement LifecycleInterface

Every plugin implements LifecycleInterface, which defines the hooks Phlix calls at each phase of the request lifecycle.

  • onInstall() — first time the plugin is dropped in
  • onEnable() — each time Phlix starts with the plugin active
  • onDisable() — when the plugin is disabled or Phlix shuts down
  • onUninstall() — when the plugin is fully removed

2. Ship a manifest.json

The manifest declares the plugin's name, version, interface version, and any dependencies.

{
  "name": "my-metadata-provider",
  "version": "1.0.0",
  "interface": "1.0",
  "lifecycle": "MetadataProvider",
  "description": "Fetches artwork from a custom source",
  "author": "Your Name"
}

3. Drop into plugins/

That's it. The plugin loader scans plugins/ on startup, validates the manifest, resolves dependencies, and wires up the lifecycle hooks. No config file editing, no registration calls.

Write your own

Start from phlix-plugin-example and implement LifecycleInterface for the hook you need — metadata provider, artwork fetcher, transcoder, notification handler. The interface is versioned, so your plugin works with the Phlix version it was built for.
