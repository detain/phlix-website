The Plugin Model

A versioned contract. A manifest. A drop-in. The loader picks it up. That's the whole magic.

LifecycleInterface + manifest schema

Every plugin implements LifecycleInterface and ships a manifest.json that declares the plugin version, the Phlix API version it targets, and the hook points it fills.

The loader reads the manifest, checks the API version compatibility, and registers the plugin's hook handlers. Drop a plugin folder into plugins/ and it's live on the next server start.

Hook points

  • metadata.provider — supply metadata for a given media item
  • scanner.process — inspect or transform a scanned file
  • transcode.profile — add a custom quality profile
  • auth.provider — add an auth mechanism
