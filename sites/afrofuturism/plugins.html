Extensibility

A plugin system
with a real contract.

Phlix's plugin architecture is built on clear interfaces and a versioned manifest. Drop a plugin in, the loader picks it up — no forking, no patching, no magic.

The plugin model

LifecycleInterface + manifest schema

Every Phlix plugin implements LifecycleInterface and ships a manifest.json. The server's plugin loader reads the manifest, validates the contract version, and hooks the plugin into the server lifecycle — install, enable, disable, uninstall — without any manual intervention.

plugins/your-plugin/
  manifest.json    # version, name, lifecycle contract
  src/
    Plugin.php  # implements LifecycleInterface

Plugins live in the plugins/ directory alongside your server installation. Phlix scans this directory on startup, reads each manifest.json, and registers what it finds. There is no database migration, no restart ritual, no configuration file to edit. Drop it in, and Phlix discovers it.

Community plugins

The Phlix ecosystem is young and growing. As more developers write plugins, a central registry will surface them. For now, the best place to find what's available is the detain GitHub org.

Write your own

The phlix-plugin-example repository is the canonical reference for building a plugin from scratch. It demonstrates the smallest possible working implementation: a metadata provider that adds cover art from a custom source.
