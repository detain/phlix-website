Plugin System

A versioned contract, a manifest schema, and a loader that just works. Drop a plugin in, Phlix finds it.

Plugin Model

LifecycleInterface + Manifest

Every Phlix plugin implements LifecycleInterface and ships a manifest.json. The loader scans the plugins directory on startup, validates the manifest against the schema, and registers the plugin's hooks and services. 

{
  "name": "my-metadata-provider",
  "version": "1.0.0",
  "schema": "1",
  "lifecycle": "MetadataProvider",
  "provides": ["metadata:tvdb", "metadata:tmdb"],
  "requires": ["phlix-core >=2.0.0"]
}

See phlix-plugin-example for the smallest working starter — a reference metadata provider plugin you can fork and build from.

Write your own

The plugin system is designed to be simple to reason about. You only need to implement the lifecycle interface your plugin type requires, write a manifest, and drop the directory into plugins/. Phlix handles the rest. 

namespace MyPlugin;

use Phlix\Plugin\LifecycleInterface;

class MyPlugin implements LifecycleInterface
{
    public function onEnable(): void
    {
        // Register routes, hooks, services
    }

    public function onDisable(): void
    {
        // Clean up
    }
}

Refer to phlix-plugin-example for the full reference implementation with working metadata fetching, routing, and service registration.
