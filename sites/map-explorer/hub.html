Phlix Hub

Reach your home server from anywhere — no port forwarding, no third-party tunnel.

What the Hub Does

Phlix Hub is a reverse-tunnel relay that solves the NAT problem. When your Phlix server starts, it connects outbound to the Hub and establishes a persistent tunnel. When you open a client from anywhere in the world, the Hub routes your request through that tunnel to your server — no ports opened on your router, no dynamic DNS to maintain.

How it works

  1. Server starts, connects outbound to Hub (port 443, TLS)
  2. Hub assigns a unique server ID and keeps the tunnel alive
  3. Client authenticates with Hub, requests connection to server ID
  4. Hub bridges the client connection through the server's tunnel
  5. All traffic flows through the Hub — no direct server access needed

Self-host or Use the Public Hub

The Hub is open-source (phlix-hub) and you can run your own instance. This gives you:

  • ✦ Full control over your relay infrastructure
  • ✦ No data traversing a third-party server
  • ✦ Ability to register multiple servers under your own Hub
  • ✦ Run it on the same host as your Phlix server or separately

Alternatively, use the public Hub at hub.phlix.dev — sign in with your GitHub account and register your server in seconds.

Hub Mode in Clients

Every Phlix client supports Hub mode. When enabled, the client connects to the Hub instead of searching for servers on the local network. This means:

  • ✦ Access your server from anywhere in the world
  • ✦ Same interface as local playback — no compromises
  • ✦ SyncPlay works across the Hub connection too
  • ✦ Local network mode still available when you're home

Hub mode is built into the Windows, Roku, and Mobile clients. Samsung Tizen clients can be configured to use Hub mode as well.
