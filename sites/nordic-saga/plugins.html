Plugins

A real contract. A versioned manifest. Drop a plugin into the forge and the loader picks it up. Nothing is decoration. Everything has purpose.

Plugin Model

Phlix plugins implement the LifecycleInterface and ship a versioned manifest. The loader scans the plugins/ directory at startup and registers each plugin's hooks, routes, and metadata providers automatically.

The plugin contract is versioned using semantic versioning — a plugin targeting version 1.x will continue working as the contract evolves, giving authors and server operators stability across upgrades.

plugins/
  my-plugin/
    manifest.json     # name, version, contract version
    src/
      Plugin.php      # implements LifecycleInterface

Ecosystem Plugins

The growing plugin ecosystem covers metadata providers, subtitle sources, hardware integrations, and more. See the phlix-server repository for the current plugin list.

Write Your Own

The smallest working plugin is the phlix-plugin-example reference. It demonstrates the full plugin lifecycle — onEnable, onDisable, route registration, and metadata provider hooks.

Clone it, implement your idea, and drop it into your server's plugins/ directory. The forge will know it when it sees it.

git clone https://github.com/detain/phlix-plugin-example
# read README.md for the full contract docs
