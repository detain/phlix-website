Plugins

Extend Phlix with a versioned plugin contract — drop in, the loader picks it up.

Plugin Model

Phlix uses a LifecycleInterface plus manifest schema for plugin discovery. Implement the interface, ship a manifest, drop the plugin into plugins/ — the loader handles the rest.

The interface covers initialization, runtime hooks, and shutdown, so plugins can inject metadata providers, add transcoding pipelines, extend the UI, or register new API endpoints.

Minimal Manifest 

{
  "name": "my-metadata-provider",
  "version": "1.0.0",
  "entry": "MyPlugin.php",
  "lifecycle": "metadata"
}

Ecosystem Plugins

The plugin ecosystem is growing. Community plugins can provide alternative metadata sources, additional client integrations, or specialized transcoding profiles.

Check the plugins directory in phlix-server for current offerings.

Write Your Own

Start with phlix-plugin-example — the reference metadata-provider plugin that shows the smallest working implementation.

It demonstrates plugin structure, manifest format, lifecycle hooks, and how to register with the server. Fork it and build your own.
