Plugins

Extend Phlix with a clean, versioned plugin contract.

Plugin architecture

Each plugin ships a manifest.json that declares its version, dependencies, and lifecycle hooks. The PluginLoader validates the manifest against the current schema version before activating anything.

LifecycleInterface

Plugins implement one or more of:

  • onInstall() — run once after the plugin is dropped into the plugins directory
  • onUpgrade($fromVersion) — run when the plugin version changes
  • onUninstall() — cleanup when the plugin is removed
  • onReady() — called after all plugins are loaded and the server is ready

Minimal example

{
  "name": "my-plugin",
  "version": "1.0.0",
  "schema": "1.0",
  "requires": { "phlix": ">=1.0.0" },
  "hooks": ["onReady"]
}

Ecosystem

  • phlix-plugin-example — the smallest working plugin. Use as a starter.
  • phlix-plugin-auth-ldap — LDAP / Active Directory auth backend.
  • phlix-plugin-storage-s3 — store media on S3-compatible object storage.
  • phlix-plugin-import-plex — import libraries from a Plex server.

Publishing

Submit a PR to the phlix-hub repo to list your plugin in the Hub. The Hub also handles distribution if you don't want to host releases yourself.
